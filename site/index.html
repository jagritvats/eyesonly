Git, but not all-or-nothing.

Works on the GitHub repo you already have, with no server to run. Your .env lives next to the code, encrypted for the people who should read it, and everyone keeps using plain git. Private branches are sealed on the host. When they must be invisible and pushes rejected before they're stored, add the Eyes Only server. Same commands.

One client, two ways to enforce

A commit hashes its whole tree, so git can't leave a file out for one person. Eyes Only keeps the tree identical for everyone and controls who can read the blobs, then checks every commit: on each laptop and in CI in GitHub mode, or on the server before anything is stored.

everywhere · client

Encrypted files

A clean/smudge filter seals protected paths with AES-256-GCM, wraps the key per reader with X25519 and signs it with Ed25519. Unchanged files don't churn, and git diff shows plaintext to readers.

everywhere · policy

A signed policy

Who reads and writes which path, plus everyone's public key, signed by an admin. Clients refuse unsigned changes, rollbacks and a policy loosened on a feature branch, and pin the admin key.

GitHub mode · verify

Checked before merge

eyesonly verify runs the server's checks in a pre-push hook and as a required CI check: no plaintext secrets, no forged or moved ciphertext, no unsigned policy edits reach main.

server · proxy + hook

Rejected before it's stored

An authenticating proxy hides private/* (protocol v0, so hidden commits can't be fetched by SHA), and a pre-receive hook refuses plaintext, unauthorized edits and private history merged into main.

GitHub mode or server?

Start with GitHub mode. Add the server when you need branches only some people can see, or a plaintext secret must never reach the host, even from someone who skips the client.

What Eyes Only doesn't do

Security tools lose trust by over-claiming, so here are the limits. Details are in THREAT_MODEL.md.

Revocation isn't retroactiveSomeone who could read a secret has seen it. eyesonly offboard <user> re-encrypts and writes the rotation checklist.
File names and timestamps are visibleOutsiders see that .env exists and when it changed, but not what's in it.
GitHub mode detects, the server preventsWithout a server, a plaintext push from someone who skips the client is on the host until CI flags it. Rotate it.
The server sees private branchesIt never sees file plaintext, but private refs are ordinary objects on the server.
Run it behind TLSTokens are bearer credentials. Put Caddy or nginx in front.

Quickstart

Install once: npm i -g eyesonly or brew install jagritvats/tap/eyesonly (Node 22+, git 2.40+, Linux, macOS, Windows). Then pick a mode; the commands afterwards are the same.

GitHub mode 2 minutes · no server

# admin, in the repo you already have (GitHub, GitLab, any git host) eyesonly keygen alice eyesonly init --commit # encrypts .env and secrets/** for @core git push # each teammate eyesonly keygen bob eyesonly clone git@github.com:acme/app.git && cd app eyesonly join # commit .eyesonly/requests/bob.pub in a pull request # admin, once the request is merged eyesonly grant bob --from-request && git add .eyesonly && git commit -m "grant bob" eyesonly rekey && git commit -am "rekey" && git push # bob git pull && eyesonly pull-policy # .env is now plaintext for bob only

Then make eyesonly verify a required check (workflow, no secrets), so nothing unverified merges into main.

Add the server when you need hard guarantees

eyesonly keygen alice # the admin's own identity eyesonly-server init --admin "$(eyesonly whoami | tail -1)" --repo app.git eyesonly-server serve --port 8787 # init printed alice's token # starter policy: @core reads .env and secrets/**, private/* branches are @core-only # or with automatic HTTPS: docker compose up -d (deploy/ in the repo) # each developer: send your card (eyesonly keygen) to the admin, get a token eyesonly clone https://alice:<token>@git.example.com/app.git

Moving an existing repo onto the server?

# GitHub stays as a second remote git remote rename origin github git remote add origin https://alice:<token>@git.example.com/app.git git push -u origin --all && git push origin --tags eyesonly setup && git add .gitattributes && git commit -m "eyesonly" && git push # teammate with an existing clone: pull first, then setup git remote set-url origin https://bob:<token>@git.example.com/app.git git pull && eyesonly setup

Secrets already committed in plaintext? Rotate them; the guide shows how to strip them from history (the server rejects that history until you do).
